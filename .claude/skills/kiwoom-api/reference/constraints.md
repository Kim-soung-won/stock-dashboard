# 키움 OpenAPI 제약 명세

"이 API가 우리에게 강제하는 것"만 모았다. 각 항목에 **근거**와 **그래서 코드가 어떻게
됐는지**를 붙였다. 호출 방법 자체는 `conventions.md`, TR 선택은 `playbook.md`.

근거 표기: `[스펙]` 스펙 JSON에 명시 · `[실측]` 실제 호출로 확인 · `[문서]` 키움 가이드
기준(스펙 JSON에는 없음) · `[미확인]` 아직 검증 못 함

---

## 1. 아키텍처를 결정해 버리는 제약

### 1.1 토큰이 발급 IP에 묶인다 `[스펙]`

에러 `8010` "Token을 발급받은 IP와 서비스를 요청한 IP가 동일하지 않습니다".

- 토큰 발급과 API 호출을 **같은 egress IP를 가진 프로세스**가 해야 한다.
- → **egress IP가 변동되는 서버리스(Vercel/Lambda/Cloud Run 기본)에 배포 불가.**
- → 고정 IP를 가진 단일 상주 프로세스가 필요하다. 컨테이너로 띄울 때도 outbound IP가
  고정돼야 한다(NAT 게이트웨이 등).
- 코드: `KiwoomApiError.isIpMismatch` 는 재시도 대상에서 제외하고 즉시 에러 로그를 남긴다
  — 재시도로 낫는 문제가 아니라 배포 환경 문제라는 신호이기 때문.

### 1.2 자격증명이 브라우저로 내려갈 수 없다 `[스펙]`

토큰 발급(`au10001`)은 `appkey`/`secretkey`를 바디로 받고, WebSocket 접속은 `LOGIN`에
토큰을 싣는다. 프론트에 두면 계좌 통제권을 그대로 넘기는 것이다.

- → BFF가 필수다. 브라우저는 키움을 직접 부르지 않는다.
- 브라우저 직접 호출 시 CORS 허용 여부는 `[미확인]` — 애초에 시도할 구성이 아니다.

### 1.3 유량(호출 개수) 제한이 앱 단위 `[스펙]` / 수치는 `[미확인]`

에러 `1700`(API별 유량) · `1701`(전체 유량) · `1702`(그룹 유량) · `1687`(재귀 호출 제한).
**구체적 수치는 스펙에 없다.**

- → 브라우저 탭마다 폴링하면 앱 전체 예산을 배수로 태운다. 모든 REST 호출은 BFF의
  단일 리미터(`kiwoom/rate-limiter.ts`)를 통과한다. 기본 `KIWOOM_RPS=4`는 **추정값**이고
  실측 후 조정해야 한다.
- → 실시간 시세를 REST 폴링으로 대체하면 안 된다. react-query에 `refetchInterval`을
  넣지 않는 이유.
- `1700` 계열을 맞으면 리미터를 비우고(`penalize`) 1초 후 1회만 재시도한다.

### 1.4 실시간은 WebSocket 전용이고 세션은 하나가 낫다 `[스펙]`+`[문서]`

- 실시간 시세·주문체결·잔고 이벤트는 `wss://api.kiwoom.com:10000` 의 `REG` 등록으로만
  받는다. REST에는 대응 TR이 없다.
- 접속 후 절차는 **스펙 JSON에 없다** `[문서]`: `LOGIN`(토큰) → `REG` → 서버가 보내는
  `PING`을 **그대로 되돌려** 유지. 스펙에는 메시지 페이로드만 정의돼 있다.
- **재접속하면 등록이 초기화된다** → 클라이언트가 등록 목록을 보관하고 다시 보내야 한다
  (`KiwoomWsSession.desired` 표 + `reregisterAll`).
- 동시 접속 허용 수는 `[미확인]`. 탭마다 연결하는 구성은 애초에 토큰 노출 때문에 못 쓰므로,
  BFF가 단일 세션을 들고 화면별 구독을 refcount로 다중화한다.

### 1.5 실전/모의 앱키가 분리돼 있다 `[실측]`

에러 `8030`(Appkey) · `8031`(Token) "투자구분(실전/모의)이 달라서 사용할 수 없습니다".

- 실전 앱키로 `mockapi.kiwoom.com`을 부르면 토큰 발급 단계에서 막힌다(반대도 동일).
- → 도메인과 키의 투자구분이 **쌍으로** 맞아야 한다. `.env` 의 `KIWOOM_ENV` 하나로
  도메인이 결정되므로, 키를 바꿀 때 이 값도 함께 바꿔야 한다.
- 모의투자에서 각 TR이 실제로 동작하는지는 스펙에 표기가 없다 `[미확인]` — 스펙의
  `mockDomain` 은 "주소"일 뿐 지원 보장이 아니다.

### 1.6 주문은 멱등하지 않다 `[스펙 구조상]`

주문 API(`kt10000`~`kt10003`)에 클라이언트 요청 ID를 받는 필드가 없다. 같은 요청을 두 번
보내면 주문이 두 건 생긴다.

- → 멱등키는 **우리가** 만들어 DB unique 제약으로 막는다. 전송 전에 저널 행을 선점한다.
- → 네트워크 타임아웃처럼 결과를 모르는 상황에서 **재시도하면 안 된다.**
  react-query 뮤테이션의 `retry: false`, 폼 전송 중 버튼 잠금이 이 제약에서 나왔다.
- 응답 `ord_no`는 **접수**일 뿐이다. 체결 확정은 실시간 `00`(주문체결)의 `913` 주문상태로만
  알 수 있다 → 접수와 체결 사이 상태를 보관할 저장소가 필요하다(= DB가 필요한 진짜 이유).

## 2. 요청/응답 형태의 제약

| 제약 | 근거 | 영향 |
| --- | --- | --- |
| **342개 TR 전부 `POST` + JSON**. GET·쿼리스트링 없음 | `[스펙]` | REST 클라이언트가 단일 `call(apiId, body)` 로 성립 |
| URL은 **기능 그룹**이고 실제 TR은 `api-id` **헤더**가 구분 | `[스펙]` | URL 하나에 최대 35개 TR. URL을 손으로 관리하지 않고 `API_CATALOG` 에서 얻는다 |
| 헤더 4개(`api-id`·`authorization`·`cont-yn`·`next-key`)가 스펙의 `requestIo` 안에 필드처럼 섞여 있다 | `[스펙]` | 스펙을 읽을 때 헤더/바디를 갈라야 한다(`kiwoom_spec.py show` 가 분리해 준다) |
| **HTTP 200이어도 `return_code != 0` 이면 실패** | `[스펙]` | 상태코드로 판정하는 클라이언트는 실패를 성공으로 읽는다 |
| 토큰 엔드포인트는 원인 코드를 `return_msg` 안에 `[8030:...]` 형태로 끼워 준다 | `[실측]` | `return_code` 는 2/3 처럼 뭉뚱그려진다 → 하위 코드를 파싱해야 원인을 알 수 있다 |
| 연속조회는 **응답 헤더** `cont-yn`/`next-key` → 다음 **요청 헤더**로 | `[스펙]` | 바디가 아니다. 단, WebSocket 조건검색만 **바디** `cont_yn`/`next_key` (하이픈 vs 언더스코어) |
| 응답 1페이지 건수 상한이 있다 | `[실측]` | `ka10081` 일봉 600건, `ka10080` 5분봉 900건. 더 필요하면 연속조회 필수 |

## 3. 값 표기의 제약 (파싱 함정)

| 제약 | 근거 | 대응 |
| --- | --- | --- |
| **모든 값이 문자열** | `[스펙]` (`type` 대부분 String) | 숫자 변환은 직접. 빈 문자열 `""` 이 "값 없음"(null 아님) |
| **가격에 붙은 부호는 음수가 아니라 전일대비 방향** | `[스펙]`+`[실측]` | `"-20800"` = 20800원 하락, `"+281500"` = 281500원 상승. 값은 `parseAmount`(절대값), 방향은 `pred_pre_sig`/`pre_sig` |
| 단위가 필드마다 다르다 | `[스펙]` (desc에 명시) | 원 / 천원 / 백만원 / 억원 / %. 예: 거래대금·실시간 FID `14` 는 백만원 |
| 백분율은 부호 포함 소수점 둘째 자리 문자열 | `[스펙]` | |
| **실시간 타입 코드는 대소문자를 구분한다** | `[스펙]` | `0G`(ETF NAV) ≠ `0g`(주식종목정보), `0U` ≠ `0u`. PowerShell `ConvertFrom-Json` 이 스펙 파싱에 실패하는 이유 |
| **종목코드 표기가 TR 계열마다 다르다** | `[실측]` | 시세: `005930` / `039490_NX`(NXT) / `039490_AL`(SOR). 계좌(`kt00018` 종목번호, 실시간 `00` 의 FID `9001`): **`A005930`**. 통일하지 않으면 잔고와 실시간 틱이 다른 키가 되어 매칭이 조용히 실패한다 → `normalizeStockCode()` |
| 거래소 구분 파라미터가 조회계와 주문계에서 이름도 값도 다르다 | `[스펙]` | 조회 `stex_tp`(`K`/`N`/`A`), 주문 `dmst_stex_tp`(`KRX`/`NXT`/`SOR`) |
| 일부 TR만 응답 키가 camelCase | `[스펙]` | `ka10099` 종목정보 리스트는 `list[].code/name/marketName`. 나머지는 snake_case |
| **`ka10099` 의 시장 구분은 배타적이지 않다** | `[실측]` | 코스피(`mrkt_tp=0`) 2478건에 KOSPI 상장 ETF 1163건이 포함돼 있고, 같은 코드가 ETF 목록(`mrkt_tp=8`)에도 나온다. 응답 `marketName` 으로 분류하면 "코스피를 물어봤는데 etf·unknown 이 섞이는" 결과가 되고, 코드 단일 키로 캐시하면 나중 조회가 앞의 것을 덮어써 **같은 요청이 호출마다 다른 개수를 준다**. 캐시는 `(요청 시장, 코드)` 복합키로 둔다 |
| 거래량 필드에 오버플로 센티넬이 섞인다 | `[실측]` | `ka10030` 거래량 상위 1위가 `4294967295`(UINT32 최댓값)로 왔다. 실제 수량이 아니므로 null 로 떨어뜨린다 |
| 순위 TR 의 가격이 "현재가"가 아닐 수 있다 | `[스펙]` | `ka00198` 은 `past_curr_prc`(기준 시점 주가)를 준다. 실측에서 삼성전자 270,000원(기준) vs 현재가 281,500원. 화면에 "현재가"로 표기하면 오해를 만든다 |
| 날짜·시간은 문자열 | `[스펙]` | `yyyyMMdd`, `HHmmss`, 분봉 `cntr_tm` 은 `yyyyMMddHHmmss` 14자리(일봉 `dt` 8자리와 다름) |

## 4. 시간의 제약 (장 운영)

실시간 `0s`(장시작시간) FID `215` 장운영구분 `[스펙]`:

| 코드 | 시각 | 의미 |
| --- | --- | --- |
| `0` | 08:40~ | 장 시작 전 알림 |
| `3` | 09:00 | 장 시작 |
| `2` | 15:20~ | 장 마감 알림 |
| `4` | 15:30 | 장 마감 |
| `8` / `9` | 15:30 후 / 18:00 후 | 정규장 마감 / 전체장 마감 |
| `a` / `b` | 15:40 / 16:00 | 시간외 종가매매 시작 / 종료 |
| `c` / `d` | 16:00 / 18:00 | 시간외 단일가 시작 / 종료 |
| `P`~`V` | | NXT 프리·메인·애프터마켓 알림 |

- **장외 시간에는 실시간 체결(`0B`)이 오지 않는다.** 등록(`REG`)은 성공하고 조용하다 —
  구독이 잘못된 것과 구분이 안 되므로, 화면에 장 상태와 업스트림 상태를 함께 띄운다.
- 개발·테스트 계획을 세울 때: REST 조회와 WebSocket `LOGIN`/`REG`는 장외에도 검증 가능,
  틱 흐름은 09:00~15:30에만 확인 가능.

## 5. 아직 확인하지 못한 것 `[미확인]`

실측으로 채워야 하는 값들. 추측으로 코드에 상수를 박지 않았다.

| 항목 | 지금 상태 |
| --- | --- |
| 초당/분당 허용 호출 수 (`1700`/`1701`/`1702` 임계치) | `KIWOOM_RPS=4` 로 보수적으로 가정 |
| 한 `REG` 메시지에 넣을 수 있는 종목 수 | 스펙의 `item` 길이 200 → 제한이 있어 보이나 단위(요소별/전체) 불명. 현재 화면당 최대 100개로 계약에서 제한 |
| WebSocket 동시 접속 허용 수 | BFF 단일 세션이라 문제되지 않음 |
| 접근토큰 유효기간 | `expires_dt` 를 그대로 신뢰하고 60초 전에 갱신 |
| 모의투자에서 지원되는 TR 목록 | 실패하면 실전으로 확인 |
| 조건검색(`ka10171`~`ka10174`) 별도 유량 | 미구현 |

## 6. 우리 구현이 아직 못 넘은 제약

제약 자체가 아니라 **우리 쪽 미구현**이므로 구분해 둔다.

- 차트는 첫 페이지만 받는다(일봉 600건 ≈ 2.4년). 더 긴 기간은 연속조회를 붙여야 한다
  (`KiwoomRestClient.callAll` 은 이미 있으니 서비스에서 쓰면 된다).
- 미국주식(`/api/us/*`)·금현물·ELW·조건검색은 계약·매퍼 없음.
- 호가창은 계약(`OrderBook`)과 BFF 매퍼까지만 있고 화면이 없다.
