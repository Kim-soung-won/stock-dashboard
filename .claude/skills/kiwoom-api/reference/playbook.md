# 목적별 API 선택 가이드

"무엇을 만들려면 어떤 api-id를 쓰나"를 정리한 표. 필드 상세는
`python scripts/kiwoom_spec.py show <apiId>`.

## A. 실시간 시세 대시보드

**원칙: 값이 변하는 것은 WebSocket, 변하지 않는 것(종목 마스터·과거 차트)은 REST 1회.**
REST 폴링을 실시간 대용으로 쓰면 유량 초과(`1700`/`1701`)로 막힌다.

실시간 계좌 반영은 WebSocket `00`(주문체결) + `04`(잔고) 를 등록한다.
`item` 을 빈 문자열로 REG 하면 계좌 전체 이벤트를 받는다(스펙 요청 예시 참고).
주문 API 응답으로 받은 `ord_no` 를 `00` 이벤트의 `9203`(주문번호)와 매칭해 주문 상태
머신을 굴리는 것이 정석. `913`(주문상태: 접수/체결/확인/취소/거부) 로 상태 전이를 판단.

## C. 주문 (투자 실행)

| 목적 | api-id | 필수 요청 |
| --- | --- | --- |
| 매수 | `kt10000` | `dmst_stex_tp`, `stk_cd`, `ord_qty`, `ord_uv`, `trde_tp`, `cond_uv` |
| 매도 | `kt10001` | 동일 |
| 정정 | `kt10002` | `orig_ord_no`, `mdfy_qty`, `mdfy_uv` |
| 취소 | `kt10003` | `orig_ord_no`, `cncl_qty` |
| 신용 매수/매도/정정/취소 | `kt10006`~`kt10009` | |
| 금현물 매수/매도/정정/취소 | `kt50000`~`kt50003` | |
| 주문 가능 금액 | `kt00010` | `io_amt`, `stk_cd`, `trde_tp`, `trde_qty`, `uv`, `exp_buy_unp` |
| 증거금율별 주문가능수량 | `kt00011` | `stk_cd`, `uv` |
| 신용보증금율별 주문가능수량 | `kt00012` | |

`trde_tp`(매매구분) 주요 값: `0` 보통(지정가), `3` 시장가, `5` 조건부지정가,
`6` 최유리지정가, `7` 최우선지정가, `10` 보통(IOC), `13` 시장가(IOC), `20` 보통(FOK),
`23` 시장가(FOK), `28` 스톱지정가, `29` 중간가, `61` 장시작전시간외,
`62` 시간외단일가, `81` 장마감후시간외. (전체 목록은 `show kt10000`)

시장가(`3`)면 `ord_uv` 는 빈 문자열로 보낸다.

**주문 구현 시 지켜야 할 것**

1. 먼저 모의 도메인(`https://mockapi.kiwoom.com`)에서 끝까지 검증한다.
2. 실전 전환은 도메인 상수 하나로 끝나게 설계하고, 실전 여부를 UI에 항상 표시한다.
3. 주문 전송은 멱등하지 않다. 재시도 로직에 그대로 얹으면 중복 주문이 된다.
   클라이언트 측 주문 키 + 전송 이력으로 중복을 막는다.
4. 주문 직전에 `kt00010`/`kt00011` 로 가능 금액·수량을 확인한다.
5. 주문 응답(`ord_no`)만으로 "체결"이라 판단하지 않는다. 접수일 뿐이다.
   체결 확정은 `00` 실시간 또는 `ka10076`/`kt00009` 로 확인한다.
6. 수량·단가는 문자열로 보낸다(숫자 타입 금지).

## D. 미국주식

같은 구조가 `/api/us/*` 로 대응된다. 주문 `ust20000`~`ust20003`,
잔고 `ust21070`, 예수금 `ust21110`/`ust21160`, 현재가 `usa20100`, 호가 `usa20101`,
차트 `usa06010`~`usa06016`, 실시간 `F5`(체결)·`FE`(체결가)·`FT`(10호가)·`F4`(주문확인),
환전 `ust31300`~`ust31302`. 목록은 `catalog-us.md`.

## E. 대시보드 구성 시 실무 메모

- 실시간 구독은 `grp_no` 로 화면 단위 그룹을 나누면 화면 전환 시 `REMOVE` 가 쉽다.
- 한 종목 화면에는 보통 `0B`+`0D`(+`0H` 장전) 를 같은 그룹으로 등록한다.
- FID 값은 문자열·부호 포함이므로 서버(또는 클라이언트 어댑터) 한 곳에서
  숫자·부호·단위를 정규화한 도메인 모델로 변환한 뒤 UI에 넘긴다.
  (스펙 필드명을 UI 컴포넌트까지 그대로 끌고 가면 유지보수가 무너진다)
- 과거 차트는 REST로 받아 캐시하고, 실시간 체결(`0B`)로 마지막 봉만 갱신한다.
- 장 시작/종료는 `0s` 로 받고, 장외 시간에는 폴링을 멈춘다.
