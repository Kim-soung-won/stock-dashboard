# 개발자 문서 (docs/)

이 폴더는 **개발자 공유용** 문서 경로다. 코드에 흩어진 정보를 사람이 읽고 공유하기 좋은
형태로 모아둔다. AI 작업 지침(`CLAUDE.md`)과 달리 규칙이 아니라 **현황·이력·설계**를 담는다.

## 문서 지도

| 문서 | 무엇을 | 언제 본다 |
| --- | --- | --- |
| [FEATURES.md](./FEATURES.md) | **기능 현황표** — 기능별 상태·엔드포인트·화면·스펙(테스트) | "지금 뭐가 되고 뭐가 남았나" |
| [CHANGELOG.md](./CHANGELOG.md) | **진행 이력** — 기능 묶음별로 무엇을 왜 넣었나 | "이건 언제·왜 들어왔나" |
| [ERD.md](./ERD.md) | 데이터 모델(Prisma → Mermaid) | DB 구조·제약 확인 |
| [../ARCHITECTURE.md](../ARCHITECTURE.md) | 설계 배경·결정 근거 | "왜 이렇게 만들었나" |
| `/docs` (실행 중 BFF) | Swagger UI — API 계약(요청/응답 스키마) | 엔드포인트 직접 호출·계약 확인 |

기능 인벤토리의 **1차 출처**는 각 앱의 `CLAUDE.md`(`apps/api`·`apps/web`)다 — 계약·라우트·
슬라이스와 가장 가까이 산다. `FEATURES.md`는 그것을 **사람이 공유하기 좋게 롤업**한 뷰다.

## 유지보수 규칙

기능을 추가/변경/삭제하면 **같은 변경에서**:
1. 해당 앱 `CLAUDE.md`의 기능 표 갱신 (엔드포인트는 계약 → `docs/openapi.ts` 도 함께)
2. `FEATURES.md` 행 갱신 (상태·엔드포인트·화면·스펙)
3. 사용자에게 드러나는 변화면 `CHANGELOG.md`에 항목 추가 (기능 묶음 단위)

새 기능은 계약을 고정하는 테스트(spec)와 함께 넣는다 — spec 이 없으면 "미명세"로 본다
(루트 `CLAUDE.md`의 "테스트" 규칙).
