### 리더보드 추이 차트를 일별 종가 기준으로 전환
장중 5분 간격 스냅샷은 초기 미세 변동까지 톱니처럼 튀고 가로축 대부분이 장 시작 전
평탄 구간에 낭비됐다. 스냅샷을 **평일 장마감 15:30(KST)에 하루 한 점(종가)** 만 적재하도록
바꿨다(`@nestjs/schedule` 크론, 재시작·중복 실행 시 그날 이미 있으면 skip).
- 차트 축은 **오늘 기준 고정 30일**(MM-DD 눈금·일별 점). 시즌은 조회 범위만 정하고 축엔
  관여하지 않는다 — 매 시즌 첫날에도 빈 차트가 안 생긴다.
- **데이터 없는 앞 구간·늦게 들어온 참가자는 시드(100만·0%)로 백필**해서 첫 스냅샷만 있어도
  30점이라 곡선이 바로 그려진다(0 으로 채우면 y축 scale 이 0까지 내려가 전부 납작해지고
  가짜 급등이 생겨 시드로 채운다). 중간에 빠진 날은 직전 값 이월. 시즌 초반엔 왼쪽이 대부분
  평평한 100만 baseline 이다.
- 거래일 버킷은 각 날의 **마지막 값(종가)** 을 취하므로, 기존에 쌓인 5분 스냅샷도 자동으로
  하루 1점으로 접힌다(데이터 삭제 없이도 톱니가 사라짐). `buildDailyHistory` 순수 함수로
  분리해 고정창·백필·이월·종가 선택 계약을 spec 으로 고정.

### 주봉·월봉·연봉 추가
분봉·일봉만 있던 차트에 주/월/연봉을 더했다. 세 봉은 키움 TR(ka10082·10083·10094)이
일봉(ka10081)과 **요청 파라미터·응답 필드(dt·OHLCV)가 모두 같고 응답 배열 키만 다르다** —
그래서 변환 함수 하나(`toPeriodCandles`, 기존 `toDailyCandles` 를 개칭)를 공유하고, 서비스는
`interval → { TR, 배열키 }` 맵으로 라우팅만 나눈다. 차트 토글에 주·월·연 버튼 노출.
- 삼성전자 실측: 주봉 300 / 월봉 240 / 연봉 30개 정상 조회. getCandles 라우팅 spec 추가.

### 실계좌 조회 스위치 (ACCOUNT_ENABLED)
실전(`KIWOOM_ENV=real`) 환경에서 실계좌 잔고·미체결 조회를 **환경변수로 잠시 끌 수 있게** 했다.
- `ACCOUNT_ENABLED=false`(대소문자 무관, 기본 활성)면 `AccountEnabledGuard` 가 `/api/account/*`
  를 503(사유 포함)으로 막는다. health 에 `accountEnabled` 를 실어, 프론트는 잔고 메뉴(프로필
  드롭다운)와 잔고 페이지를 **감춘다**(북마크 직행 시엔 안내 문구).
- **페이퍼 트레이딩·시세·주문(trading)에는 영향 없다** — 실계좌 잔고/미체결 조회만 끈다.

### 매매 확인 다이얼로그 — 체결 전 예수금 영향 안내
시장가라 사용자는 **얼마가 빠져나가는지 모른 채** 매수/매도 버튼을 눌러야 했다. 이제
버튼을 누르면 곧바로 체결하지 않고 확인 창을 띄운다.
- 거래대금 · 수수료 · 거래세(매도) · 결제/정산금액 · **체결 후 예수금**(1,000,000원 →
  215,383원 식)을 나눠 보여주고, 확정을 눌러야 체결한다.
- 예수금·보유수량이 모자라면 사유를 보여주고 확정 버튼을 잠근다(최종 판정은 서버가 다시 한다).
- 시장가임을 숨기지 않는다 — 실제 체결가는 서버가 체결 시점에 관측한 시세로 정해져 안내
  금액과 다를 수 있다고 창에 적는다.
- 금액 계산(`previewTrade`)과 수수료율은 `@stock/contracts` 로 옮겨 **서버와 한 식**을 쓴다.
  BFF 의 `competition.constants` 는 다시 내보내기만 한다 — 식이 두 벌이면 안내한 금액과
  실제 차감액이 어긋난다. 서버 체결 결과와 예상치를 직접 대조하는 spec 으로 고정했다.
- `shared/ui` 에 `Dialog` 추가. 네이티브 `<dialog>` + `showModal()` 이라 포커스 트랩·Esc·
  배경 처리를 브라우저가 맡는다(직접 만들면 이 중 하나는 빠진다).

### 거래시간 제한 — 장외 체결 차단
장외에도 `getQuote` 는 값을 준다 — 다만 **전일 종가로 멈춰 있다**. 막지 않으면 참가자가
이미 결과를 아는 가격으로 밤새 사고팔 수 있어 경쟁이 성립하지 않는다.
- 규칙은 `@stock/contracts` 의 `isKrxRegularSession`(KST 평일 09:00~15:30, 시작 포함·
  종료 제외) 한 곳에 둔다. **서버가 강제**(체결 전 400 + 사유)하고 **화면은 같은 규칙으로**
  버튼을 잠근다 — 규칙이 두 벌이면 "버튼은 눌리는데 서버가 거부하는" 상태가 생긴다.
- 시세를 조회하기 전에 거부한다(유량도 아낀다). 시즌 창(`assertTradable`)과는 다른 축이라
  따로 판정한다: 시즌은 대회 기간, 이건 장 시간.
- 화면은 30초마다 로컬 시계를 다시 읽어 09:00·15:30 경계에서 새로고침 없이 풀리고 잠긴다.
- 판정을 시계로 하는 이유: 실시간 `0s`(장운영구분)가 더 정확하지만 장외에는 이벤트가 아예
  오지 않아 "아직 못 받았다"와 "닫혔다"를 구분할 수 없다.
- **한계**: 공휴일은 걸러내지 못한다(휴장일 달력 없음). `docs/FEATURES.md` 의 "알아둘 점" 참고.
- 실계좌 주문(`/trading/order`)은 그대로 뒀다 — 키움이 자체 검증하고 시간외 단일가·예약주문
  같은 정상 경로가 있어, 우리가 시간으로 막으면 기능을 없애는 셈이 된다.

### 신규 참가자 첫 로그인 500 수정 (포트폴리오 경쟁 상태)
`ensurePortfolio` 가 "읽어보고 없으면 만든다" 였다. 첫 로그인 직후에는 포트폴리오·체결이력·
리더보드 조회가 한꺼번에 들어오는데, 둘 이상이 동시에 "없다"고 판정하면 양쪽이 `create` 를
쏘고 늦은 쪽이 유니크 위반(P2002)으로 **500** 을 받았다 — 첫 화면이 깨지는 자리다.
- 유니크 위반을 정상 경로로 취급한다: "남이 먼저 만들었다"는 뜻이므로 그 행을 다시 읽어
  돌려준다. 제약이 "시즌당 1개"를 보장하므로 재시도가 아니라 재조회로 끝난다.
- 순위 재계산(`onPortfolioChanged`)은 **만든 쪽만** 부른다(이긴 쪽이 이미 불렀다).
- 위반이 아닌 에러, 그리고 위반인데 행도 없는 경우는 삼키지 않고 올린다.
- 회귀 spec 5개 추가(수정을 되돌리면 2개가 실패하는 것으로 유효성 확인). 실제로도 동시 요청
  8건으로 재현해 경쟁 5회가 모두 정상 처리되는 것을 확인했다.

### 화면 구조 개편 — 메인 통합·프로필 드롭다운·선택 종목 즉시 주문
메뉴가 10개로 불어나 "어디서 무엇을 하는지"가 흐려졌다. 진입점을 셋으로 정리한다 —
**로고**(메인), **상단 네비**(탐색), **프로필 드롭다운**(내 화면).
- **메인 통합**: "실시간 시세 대시보드"와 "인기 종목"은 둘 다 표에서 종목을 골라 옆 차트를
  보는 화면이라 `/`(index) 하나로 합쳤다. 메뉴 항목은 없애고 **좌측 상단 로고**가 여기로
  돌아온다. 통합 전 두 경로는 메인으로 리다이렉트한다(북마크 보호).
- **프로필 드롭다운**: 내 포트폴리오·내 프로필·잔고·손익·주문·이력 + 로그아웃을 우측 상단
  프로필 버튼에 모았다. 상단 네비에는 리더보드·종목 탐색·관심종목만 남는다.
  상시 노출이 필요한 값(SCORE/HI-SCORE·MOCK/REAL 배지)은 헤더에 그대로 둔다.
- **선택 종목 즉시 주문**: 종목을 고를 수 있는 세 화면(메인·종목 탐색·관심종목)에 차트와
  함께 **페이퍼 매매 주문 창**을 배치하고, 고른 종목을 프리필한다. 표는 `{code, name}` 을
  올려보내고(`SelectSymbol`) 페이지가 차트·주문 폼에 내린다. 실계좌 주문은 오조작 위험이
  커서 기존 `주문·이력` 화면에만 남긴다.
- **차트에 종목명 표기**: 코드만 찍히던 차트 헤더·패널 제목에 종목명을 띄운다. 이름은 고른
  표의 행에서 함께 넘어오므로 추가 조회가 없다.
- **시가총액 순 정렬**: 순위표에 `시가총액` 탭 추가. 키움에 국내 시가총액 순위 TR 이 없어
  종목 마스터의 `상장주식수 x 전일종가`로 파생해 `SymbolCache` 에 저장하고 DB 가 정렬한다
  (키움 추가 호출 0). **전일 종가 기준**이므로 장중 순위가 움직이지 않고 전일대비는 비어
  있다 — 화면에 기준을 함께 표기한다. ETF 제외.
  - `SymbolCache` 에 `lastPrice`·`listCount`·`marketCap` 칼럼 추가(마이그레이션).
    파생 칼럼이 없던 캐시는 TTL 안이어도 다시 받는다(자동 복구).

### 종목명 검색 + 관심 ★ 낙관적 갱신
종목코드를 외우고 있는 사용자는 없다. 코드만 받던 입력을 **종목명 자동완성**으로 바꾸고,
★ 토글은 서버 왕복을 기다리지 않고 즉시 반영한다.
- `GET /api/market/symbols/search?keyword,limit`(공개) — 코스피·코스닥·ETF 통합 검색.
  BFF 의 `SymbolCache` 를 질의하므로 유량을 태우지 않고, 관련도 순으로 정렬한다
  (코드 완전일치 → 이름 앞부분 → 중간 포함). 마스터 캐시는 부팅 시 배경에서 데운다 —
  ka10099 페이지네이션은 분 단위라 검색 요청 경로에 두지 않는다.
- 적용된 입력: 관심종목 추가(대시보드·관심종목 페이지, 공용 `FormAddWatch` 로 통합),
  주문 폼, 페이퍼 매매 폼. 종목 탐색 표의 검색은 이미 이름·코드 양쪽을 지원했다.
  **코드를 그대로 붙여넣는 기존 사용법은 그대로 통한다.**
- 종목이 확정되기 전에는 제출 버튼이 잠긴다 — 코드를 잘못 외워 다른 종목에 주문을 내는
  것이 가장 비싼 실수다.
- ★ 토글은 낙관적 갱신(`onMutate` 로 캐시 선반영, 실패 시 롤백). 토글이 여럿 겹치면
  마지막으로 끝나는 응답만 캐시를 확정한다(응답 역전으로 ★ 가 되살아나는 것 방지).
